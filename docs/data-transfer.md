# Перенос данных СтеноГРАФа

Раздел Dev-консоли «Перенос данных» доступен для изменения только рабочему аккаунту, привязанному к установке как владелец. Учебный код 1234 не даёт права выгружать или загружать данные, переключать демо-режим и использование ключа платформы. Учебная консоль показывает соответствующую плашку.

## Состав

- «Системный промпт» — JSON с инструкцией анализа. Этот промпт редактируется в «Секреты API → System prompt».
- «Шаблоны встреч» — JSON выбранной организации.
- «Обработанные встречи» — зашифрованный файл `.stenograf`: встречи READY выбранной организации, расшифровки, источники, версии анализа и иллюстрации, поручения, комментарии, чат, приглашения, участники и необходимые шаблоны/статусы, связанные локальные файлы. Настройки иллюстраций сохранены. Связи с автоматической синхронизацией облачных папок в этом частичном пакете отключены.
- «Всё вместе» — такой же архив для всех организаций, включая черновики и незавершённые встречи, роли, настройки организаций, инструкции и файлы инструкций, облачные подключения, историю синхронизаций, уведомления и аудит, AI-настройки и ключи. Инфраструктурные SSH-профили, приватный пароль Dev-консоли, привязка владельца, браузерные демо-сессии, JWT и мастер-ключ шифрования установки не переносятся. Ключи и OAuth-токены внутри архива защищены паролем; при импорте заново шифруются ключом целевой установки.

Пароль архива имеет длину 12–256 символов, не сохраняется в браузере или базе. В формате v2 используется scrypt N=16384/r=8/p=1 с индивидуальной солью и AES-256-GCM с индивидуальным IV. Без пароля архив не восстановить. Ограничения: до 4 ГБ материалов, 20 000 файлов, 200 000 записей и 200 МБ JSON. В предпросмотре отдельно указаны файлы, которые уже отсутствовали на источнике, например после удаления аудио по сроку хранения.

## Импорт

После проверки пароля, версии структуры данных, связей и контрольных сумм выводится предпросмотр. Изменения применяются отдельной кнопкой. Организации и встречи создаются как копии с новыми идентификаторами; существующие данные не удаляются. Пользователь с уже зарегистрированным email сохраняет свой текущий пароль. Владельцу целевой установки предоставляется доступ к импортированным организациям. Другой существующий аккаунт не получает членство и уведомления по одному совпадению email, если его пароль отличается: таких участников пригласите заново. Это предотвращает передачу доступа ранее зарегистрировавшему чужой email человеку.

Файлы копируются в отдельный каталог импорта. Записи сохраняются одной транзакцией; при ошибке транзакция и скопированные файлы откатываются. Облачные папки после импорта находятся на паузе. Незавершённые встречи и материалы требуют ручного повторного запуска, поэтому перенос не запускает платный AI автоматически. Активные приглашения перевыпускаются отозванными; при необходимости выдайте новые.

Применение архива не переносит запущенные процессы, очереди обработки и авторизованные сессии. Сервер назначения должен иметь ту же версию схемы приложения; несовместимая структура отклоняется до изменения данных. Старый JSON «Всё вместе» v1 с промптом и шаблонами по-прежнему принимается, но не содержит встреч.

## Новая установка

1. Разверните приложение штатной публикацией и зарегистрируйте рабочий аккаунт владельца.
2. Администратор сервера один раз привязывает существующий аккаунт командой `node apps/api/scripts/bind-platform-owner.mjs admin@example.com` в контейнере API с его штатными переменными окружения. Скрипт не назначает пароль и не заменяет уже заданного другого владельца.
3. В Dev-консоли выберите «Войти владельцу по email и паролю». После входа откроется рабочий доступ без дополнительного Dev-пароля.
4. Выберите архив, укажите его пароль, проверьте состав и примените импорт.
5. Проверьте организации, файлы и AI-настройки, при необходимости обновите OAuth Redirect URI у провайдеров и возобновите нужные облачные папки вручную. Профиль публикации на новом сервере настраивается отдельно.

Тесты: `DOTENV_CONFIG_PATH=.env node --import dotenv/config --import tsx --test apps/api/tests/transfer-archive.test.ts apps/api/tests/developer-access.test.ts`. Архивные тесты создают две временные схемы PostgreSQL только в локальной базе и удаляют их после проверки. Рабочие записи не импортируются и не удаляются.
