# СтеноГРАФ — отчёт о доработке, 05.11.2026

Полная приёмка ТЗ ещё не закрыта: остаются непроверенные облачные сценарии. Ниже отделены выполненные проверки от непроверенных сценариев.

## Реализовано

- Общая постоянная очередь для ручных файлов и облачного импорта, этапы обработки, восстановление задания по аренде, ограниченные повторные попытки.
- Импорт конкретного публичного файла Яндекс Диска через официальный API; проверка адреса, перенаправлений, размера и формата. Дедупликация по ID и версии файла.
- Аккаунты и папки пяти провайдеров: Яндекс Диск, Google Drive, OneDrive, Dropbox, Box. OAuth, шифрование токенов, расписания, фильтры четырёх типов файлов, рекурсия, журналы и пауза.
- Режимы «Каждый файл — новая встреча» и «Вся папка — одна встреча / проект» на главной странице и в админке. Новая версия прежнего файла остаётся в прежней встрече. Консоль разработчика управляет подключениями и общими параметрами.
- Извлечение текста документов и встроенных изображений, визуальный анализ, галерея источников и редактирование распознанного текста.
- Версии анализа, сравнение перед применением, сохранение ручных задач и статусов, отдельный диалог версии.
- Исходные изображения и отдельные AI-иллюстрации в отчёте и PDF. Модель по умолчанию `gpt-image-2.5-sunburst`. Готовая иллюстрация проверяется визуальной моделью по фактам отчёта; неподтверждённая исключается из автоматического экспорта.
- Пространство на браузер, два отдела и два клиента, административная сессия; серверные лимиты трёх обработок и трёх успешных вопросов на версию.
- По прямому уточнению владельца пароль Dev-консоли пока `1234`, как и демо-админки. Это сознательное исключение из пункта 12.3 исходного ТЗ. Ручная смена пароля сохранена.

## Что не подтверждено и что осталось

1. Обязательный сценарий «собственное видео 2–5 минут на Яндекс Диске → публичная ссылка → анализ → повтор без списания» не пройден целиком. Учебное видео создано и обработано вручную, но нет доступного аккаунта для его размещения в облаке. Код импорта и дедупликации проверен отдельно; это не заменяет облачную приёмку.
2. Нет Client ID/Secret и подключённых тестовых аккаунтов пяти провайдеров. Реальные OAuth-подключения, изменения/переименования/удаления файлов и восстановление синхронизации этих аккаунтов требуют живой проверки. Интерфейс сообщает о необходимости настройки.
3. Исходный код с историей изменений опубликован 05.11.2026: https://github.com/kalininvladimir1979/stenograf-ai-secretary, ветка `main`. Настроен remote `origin`, push проверен. Vercel: production-выпуск `dpl_BLcxPTUq2fYZFR4zQgyxFZcFTeJ5` завершён 05.11.2026. Ссылка: https://stenograf-ai-secretary.vercel.app/. В браузере проверены загрузка демо-пространства, формы новой встречи и `/api/health` (`ok: true`). Новые платные AI-операции для проверки публикации не запускались.
4. Для новых мультимодальных оригиналов пока работает ручное удаление; автоматическая политика срока хранения прежнего аудио не распространена на все новые материалы.
5. Папки используют полную сверку списка файлов вместо инкрементальных курсоров провайдеров. Многостраничные TIFF и отдельный пользовательский сценарий «Входящие документы без встречи» нуждаются в дополнительной проверке/доработке. Последнее уточнение владельца реализовано как выбор между встречей на файл и встречей на папку.
6. Перезапуск локального dev-сервера прерывает выполняющуюся из него публикацию. Для окончательного выпуска исходники зафиксированы на время выполнения; это не касается восстановления очереди обработки материалов.
