# AI-секретарь для встреч — Pro Max

Отдельное приложение для организаций: заметки и аудио встреч, проверяемый AI-анализ, задачи, шаблоны, приглашения и уведомления.

## Ссылки на проект

- Исходный код и история изменений: [GitHub](https://github.com/kalininvladimir1979/stenograf-ai-secretary).
- Опубликованное приложение на Vercel: [СтеноГРАФ](https://stenograf-ai-secretary.vercel.app/).
- Серверное приложение: [СтеноГРАФ на VPS](https://app.neurozavod.online/ai-sekretar261026/).

Репозиторий содержит исходники и синтетические тестовые материалы. Записи пользователей, база данных, локальные настройки и секреты в Git не включены.

## Локальный запуск

```bash
cp .env.example .env
docker compose up -d
npm install
npm run db:migrate
npm run dev
```

Откройте `http://localhost:5175`. API работает на `3002`, база — на `5441`. При первом запуске создайте свой аккаунт и организацию через форму регистрации. Команда `npm run db:seed` только инициализирует системные значения моделей и не добавляет демонстрационные записи.

Демо-админка открывается по `http://localhost:5175/?surface=admin`, Dev-консоль — по `http://localhost:5175/?surface=dev`. По явному уточнению владельца от 05.11.2026 для обеих пока оставлен пароль `1234`; пароль Dev-консоли можно изменить в «Безопасности». Демо-код и административная сессия относятся к пространству текущего браузера. Настройки OpenAI и SMTP организации находятся в админке; ключ разработчика и параметры OAuth — в Dev-консоли. Сохранённые секреты зашифрованы и целиком не возвращаются в браузер. Письмо по итогам встречи остаётся черновиком.

Для прежних аудиозаписей действует настраиваемая политика хранения. Новые мультимодальные оригиналы сохраняются в материалах встречи и доступны для ручного удаления; автоматическое применение срока хранения к ним требует отдельной доработки.

## Видео и локальная подготовка аудио

В форме новой встречи можно загрузить MP4, MOV, WebM, MKV или AVI. Видео принимает сервер приложения, проверяет через FFprobe и направляет в общую очередь материалов. Python-обработчик запускает локальный FFmpeg и извлекает отдельный MP3 для каждого аудиоканала (16 кГц, 48 кбит/с). Каналы разбиваются на части и распознаются отдельно с меткой источника. Для этого нужны `python3`, `ffmpeg` и `ffprobe`; внешний AI получает аудио, а не видеофайл. Каждая часть аудио остаётся меньше лимита запроса Whisper. Оригинал нового материала сохраняется до удаления пользователем. Для скачивания из облака действует настраиваемый предел, по умолчанию 512 МиБ; ручные загрузки дополнительно ограничены ресурсами сервера.

Для ручного сквозного тестирования заметок и аудио используйте материалы из [`test-data`](test-data/README.md).

## Production

Соберите `npm run build`, создайте DNS A-записи `app.<домен>`, `admin.<домен>`, `dev.<домен>` и настройте Nginx из `deploy/nginx.conf`. Эти три адреса обслуживают одно приложение, но административная и developer-поверхности закрыты паролями и не имеют публичных ссылок.

## Облака и мультимодальные материалы

В форме «Новая встреча» раздел «Материалы встречи» объединяет файлы с компьютера и импорт по ссылке. В режиме «Ссылка на файл в облаке» доступно поле «Ссылка на видеозапись или другой файл». На главной странице отдельной формы импорта больше нет. Публичный файл Яндекс Диска разрешается через официальный API метаданных и скачивания. Ссылка на папку в этом поле отклоняется. Состояние скачивания, распознавания и анализа хранится в `ProcessingJob`; файл и его версия — в `Material`. Повторная неизменённая ссылка открывает сохранённый материал. Сервер проверяет адреса, DNS и перенаправления, ограничивает загрузку и проверяет фактическое содержимое.

В «Облачных папках» настройте аккаунты Яндекс Диска, Google Drive, OneDrive, Dropbox или Box, затем добавьте папки. Для OAuth сначала нужны Client ID и Client Secret соответствующих приложений. До их настройки интерфейс сообщает «Требуется настройка разработчиком». Публичные папки Яндекс Диска доступны без OAuth. Обычному пользователю не требуется вручную получать токен облака.

У каждой папки два режима:

- «Каждый файл — новая встреча»: разные файлы создают самостоятельные встречи; новая версия того же файла остаётся связанной с прежней встречей.
- «Вся папка — одна встреча / проект»: материалы папки собираются вместе; обнаруженные в одной проверке файлы анализируются общим запуском. Новые материалы создают предложение новой версии результата.

Категории видео, аудио, изображений и документов включаются независимо. Для папки задаются рекурсия, первичный импорт, автоматический анализ и расписание с часовым поясом. Проверка работает в API-процессе с сохранённой датой следующего запуска, без открытой вкладки.

Изображения анализируются визуальной моделью, сохраняются как отдельные источники и могут быть исключены из следующего анализа. Документы извлекаются локально; страницы PDF и встроенные изображения сохраняются отдельно. Для этого нужны Python, Pillow, FFmpeg, Poppler и unrtf; они включены в production Dockerfile. PDF ограничен 40 страницами на материал. Исходные и сгенерированные изображения различаются в отчёте и PDF-экспорте.

Повторный анализ создаёт `AnalysisVersion` со сравнением перед применением. Ручные поручения и статусы сохраняются. В новой версии собственный диалог; прежний остаётся доступен для чтения. Генерация иллюстрации через `gpt-image-2.5-sunburst` не отменяет сохранение текста при ошибке модели.

В демо у браузера два клиента из разных отделов и отдельная административная сессия. Лимит AI-операций общий и хранится на сервере: по умолчанию три. У успешной версии три успешно отвеченных вопроса. Ключ выбирается по переключателю разработчика; при выключенном переключателе нужен собственный ключ демо-пространства.

## Проверки и Vercel

```bash
set -a; . .env; set +a
node --import tsx --test apps/api/tests/cloud.test.ts
node apps/api/tests/http-isolation.mjs
# Следующие проверки действительно обращаются к OpenAI и расходуют API-бюджет:
node apps/api/tests/ai-smoke.mjs
python3 test-data/multimodal-smoke.py
node apps/api/tests/media-smoke.mjs
```

`vercel.json` собирает существующий фронтенд и направляет `/api/*` в опубликованный сервер «СтеноГРАФа». Длительная обработка, PostgreSQL и расписания остаются на VPS. Приложение опубликовано на Vercel из ветки `main`; интерфейс и проксирование API проверены 05.11.2026. Встроенные OAuth Redirect URI показываются в Dev-консоли; production-адреса задаются `PUBLIC_API_URL` и `PUBLIC_APP_URL`.


## Инструкции для пользователей

Админка → «Инструкции»: текст, диктовка, загрузка файлов до 512 МБ, ссылки YouTube и публичных облачных файлов. Администратор задаёт название, редактирует материал, публикует его для участников организации или оставляет черновиком. Диктовка использует общий клиент с реальным измерителем сигнала, таймером, остановкой и отменой; распознавание не отправляет инструкцию автоматически.

Значок вопроса в шапке предлагает «Просмотреть видеоинструкции» и «Показать подсказки на странице». Первое открывает библиотеку с видео- и аудиоплеерами, изображениями, страницами PDF и текстом документов. Второе запускает прежние пошаговые подсказки. Окно закрывается крестиком, Escape и кликом снаружи, поддерживает разворачивание.

YouTube и Google Диск используют встраивание провайдера; сервис может запретить просмотр или потребовать вход, поэтому доступна ссылка на источник. Публичные ссылки Яндекс Диска разрешаются через API, прямые HTTPS-файлы других хранилищ импортируются с проверкой DNS и каждого перенаправления. Страницы просмотра, не отдающие файл, остаются внешними ссылками. Для закрытых ссылок нужно предоставить публичный доступ либо загрузить файл вручную.

PDF отображается по подготовленным локально страницам (до 40 страниц). Из DOCX, XLSX, PPTX и RTF извлекается текст; для прочих форматов сохраняется скачивание оригинала. Видео и аудио воспроизводятся, если браузер поддерживает их кодек. Инструкции хранятся в БД и `storage/instructions`, изолированы по организации и не являются промптами AI. Файлы выдаются по временным ссылкам с повторной проверкой членства.

Проверка без платных AI-запросов: `node apps/api/tests/instructions-http.mjs` с переменными из `.env`; она создаёт и удаляет собственные синтетические данные и проверяет права, черновики, загрузку, потоковую выдачу и страницы PDF.
